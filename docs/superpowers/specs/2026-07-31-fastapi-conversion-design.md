# FastAPI Conversion Design

## Overview

Convert the existing Streamlit application to a FastAPI REST API backend. The frontend will be handled separately - this spec covers only the backend API implementation.

## Current State

The application is a Streamlit monolith with:
- Login/Register functionality
- Items CRUD operations
- Admin user management
- MongoDB Atlas database
- JWT authentication

## Target Architecture

### Project Structure

```
server/
├── __init__.py
├── main.py          # FastAPI app entry point
├── config.py        # Configuration via environment variables
├── database.py      # MongoDB connection (renamed from db.py)
├── auth.py          # Authentication logic (updated)
├── dependencies.py  # FastAPI dependencies (JWT auth, db)
├── routers/
│   ├── __init__.py
│   ├── auth.py      # Auth routes (login, register)
│   ├── items.py     # Items CRUD routes
│   └── admin.py     # Admin user management routes
└── models/
    ├── __init__.py
    ├── user.py      # User Pydantic models
    └── item.py      # Item Pydantic models
```

### API Endpoints

**Auth:**
- `POST /api/auth/login` - User login
- `POST /api/auth/register` - User registration

**Items (Protected):**
- `GET /api/items` - Get all items
- `POST /api/items` - Create new item
- `DELETE /api/items/{name}` - Delete item by name

**Admin (Admin Only):**
- `GET /api/admin/users` - Get all users
- `DELETE /api/admin/users/{username}` - Delete user

**Health:**
- `GET /api/health` - Health check endpoint

### Authentication

- JWT token via Bearer header
- Token expiration: 24 hours
- Password hashing: bcrypt (unchanged)

### Configuration

Environment variables via pydantic-settings:
- `MONGODB_URI` - MongoDB connection string
- `MONGODB_DB_NAME` - Database name
- `JWT_SECRET_KEY` - JWT signing key

### Dependencies

- `fastapi` - Web framework
- `uvicorn` - ASGI server
- `pymongo` - MongoDB driver
- `bcrypt` - Password hashing
- `PyJWT` - JWT tokens
- `pydantic-settings` - Configuration management

## Data Flow

1. Client sends request to FastAPI endpoint
2. FastAPI validates request using Pydantic models
3. Dependencies handle authentication (JWT verification)
4. Route handler processes business logic
5. Database operations via pymongo
6. Response returned as JSON

## Error Handling

- HTTP 400: Bad request (validation errors)
- HTTP 401: Unauthorized (invalid/missing token)
- HTTP 403: Forbidden (insufficient permissions)
- HTTP 404: Not found (resource doesn't exist)
- HTTP 500: Internal server error

## Testing

- Manual testing via curl or API client
- Health check endpoint for monitoring
- API documentation via Swagger UI (auto-generated by FastAPI)

## Migration Notes

- Keep existing `client/` directory for reference
- Update `requirements.txt` with FastAPI dependencies
- Create `.env.example` for environment variables
- MongoDB database schema remains unchanged
